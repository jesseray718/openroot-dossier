### Credibility checklist (non-negotiable for any public OpenRoot artifact)
- Solves a real, clearly stated problem
- New user can install and run in under five minutes
- Contains at least one working example
- Has a clear license
- No secrets, keys, or personal data committed
- At least one automated test or validation command
- README states limitations and known issues
- Commits describe meaningful changes
- Releases or tags mark working milestones
- Documentation explains how others can contribute

### Minimum project skeleton
README.md · LICENSE · CONTRIBUTING.md · CODE_OF_CONDUCT.md · CHANGELOG.md · SECURITY.md · src/ · tests/ · docs/ · .github/workflows/tests.yml

### Portfolio principle
A certificate confirms attendance. A working, documented, reproducible tool that a stranger can clone, run, and improve demonstrates capability.
