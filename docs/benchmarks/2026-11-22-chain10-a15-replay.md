# Ten-step captured-evidence replay: OptiPlex to A15

Date: 2026-11-22

## Result

An operator-reported run captured ten dependent answers on an OptiPlex using ten local model request attempts. An A15 then verified the captured evidence and dependency chain and reproduced all ten answers byte-for-byte with zero model requests.

Fresh capture and generation took 419.301586 seconds. A15 bundle loading, full verification, and per-record reverification/replay took 0.036203 seconds (36.203 milliseconds), excluding transfer and interpreter startup. These are different operations on different hardware, not a model-inference speed comparison.

This report transcribes the operator-supplied completion and replay receipts. The full private bundle and answer content were not independently inspected for this publication.

## Protocol and integrity

Protocol identifier: `openroot-chain10-captured-replay-v1`.

The runner was configured for sequential requests to the local `qwen2.5:3b` model, with temperature 0, seed 42, a 4,096-token context setting, and a 600-token output limit. These settings are protocol configuration, not a claim of universal deterministic generation.

Each captured record binds the question, preceding-answer hash, effective dependent input, prompt hash, captured context, evidence snapshot, answer hash, and preceding-record hash. Full captured source bodies accompany the private bundle. The phone validates captured source bytes and reconstructs the recorded context before returning the stored answer.

The fresh benchmark used the existing retrieval/context functions and direct local model requests in an isolated harness. It did not register these captures in the production pathway store. The A15 run used the benchmark's captured-evidence reader, not the production phone router.

Python socket and child-process operations were denied by an audit hook in the replay worker. This is not OS-level network isolation and does not establish airplane-mode operation.

## Interpretation and limitations

This demonstrates the bounded capability to produce dependent captured results on a larger machine and reuse those exact results with evidence/dependency checks on a smaller device without additional model requests.

It does not establish:

- Answer correctness, semantic sufficiency, or successful progression through all ten reasoning tasks. Answer review remains pending.
- General retrieval quality or relevance merely because evidence was retrieved.
- Current applicability, source freshness on the phone, live pricing, or refreshed recommendations.
- Model-inference speedup, energy savings, or superlinear scaling. Energy was not measured.
- Production phone-router integration, a stable product release, or green GitHub CI.

One response reached the output-token limit. Console output also showed the same answer-hash prefix for steps 3, 4, and 5; their full saved texts require review before making reasoning-quality claims. Exact replay can faithfully preserve an incorrect, repeated, or incomplete answer.

Timing excludes transfer, interpreter startup, and public-report writing. Phone measurements used an already running worker and may benefit from warm storage caches. No wall-time ratio is presented as an algorithmic or hardware speedup.
